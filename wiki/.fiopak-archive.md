> Applies to Fio 3.1.0.0611 (CANARY).

`.fiopak` is Fio's archive format: an ordinary ZIP file with a fixed member layout. The extension is used for two different things, which share the "data only, project-relative paths" rule but have different contents and readers:

* a **game package** (`packages/<title>.fiopak`): one or more maps, the cutscenes and assets they reference, and a manifest. Exported by the editor and played by the editor or by the standalone [Fio Player](https://github.com/ViciousSquid/Fio/wiki/Fio-Player-(Android));
* a **category asset archive** (`assets/<category>.fiopak`): the engine's own stock assets for one category.

Neither kind is ever extracted to disk. Both are read in place, member by member. Neither may contain code: a game package with any member under a top-level `plugins/` directory is rejected.

# Game packages

## Using them

* **Tools > Export Game Package...** (`Ctrl+Shift+E`) opens the export form in place of the Properties dock's content (`MainWindow._show_overlay`). Fill in **Package Title** (required), **Author**, **Version** (pre-filled `1.0.0`) and **Description**, press **Export...** and choose a file; the dialog starts in `packages/` with the name `<title>.fiopak`.
* **Tools > Play Game Package...** asks for a `.fiopak` (starting in `packages/`) and plays it. The [Asset Browser](https://github.com/ViciousSquid/Fio/wiki/Asset-Browser)'s Maps tab can list `packages/`; double-clicking a package there does the same.
* A package is launched in the game window (kiosk mode: all editor chrome hidden, window mode from `[Kiosk] window_mode`) unless `[Kiosk] launch_in_editor` is true (Settings > Play Modes), in which case its start map is opened in the editor without starting Play.

## Container and layout

The archive is written with `zipfile.ZIP_DEFLATED`. Member names use forward slashes and are relative to the project root.

```text
metadata.json                 manifest
maps/<name>.json              the entry map and every map reachable from it
cutscenes/<name>.json         cutscenes named by the maps
assets/textures/...           referenced assets, at their project-relative paths
assets/models/...
assets/sprites/...
assets/sounds/...
```

### `metadata.json`

Written by `PackageExporter.export` as JSON with a 2-space indent. It is the dictionary returned by `editor/package_dialog.py: PackageMetadataDialog.build_metadata` with `map_path` set.

| Key | Type | Written by the exporter | Meaning |
| --- | --- | --- | --- |
| `title` | string | Yes | Package title. `FioPackage.title` returns `"Untitled"` when absent or empty. |
| `author` | string | Yes | |
| `version` | string | Yes | Free text. This is the package's own version, not the map format version. |
| `description` | string | Yes | |
| `map_path` | string | Yes | Archive path of the entry map, for example `maps/Office_Corridor.json`. Always the path the current map was stored under. |
| `plugins` | list of strings | No | Names of plugins that must already be installed on the host. Read by `FioPackage.required_plugins`; the Fio Player (`player/world.py: PlayerWorld`) refuses a world whose required plugin is not installed (`This world requires an installed plugin: <name>`). |

Readers also accept the manifest under the older name `manifest.json` (`metadata.json` is tried first), and the entry map under the keys `start_map` or `main_map` (after `map_path`). A package with no manifest is valid: the entry map is then the first map in sorted order.

### Map format inside a package

The editor saves [map version 5](https://github.com/ViciousSquid/Fio/wiki/Map-format-(.json)). `PackageExporter._player_layout` writes every map whose `version` is 5 or later through `engine.brush_placement.export_world_level`, so **a packaged map carries `"version": 4`**: an angled brush's planes in world space with its `pos`/`size` set to their bounds. The conversion is lossless. A map file whose `version` is below 5 (the shipped maps are version 3) is copied byte for byte. Both readers bring every brush record to the in-memory layout when they load it (`EditorState._deserialize_brushes` on the desktop, `player/world.py: PlayerWorld.__init__` in the player): play-state keys dropped, face materials migrated or stray per-tag copies dropped, world-space planes localised.

## How the exporter chooses the contents

`editor/package_exporter.py: PackageExporter(editor_state, root_dir).export(output_path, metadata, current_map_path, parent_widget=None)` returns `(success, errors)`. Everything it writes comes from inside the project: a map or asset reference that is absolute or climbs out with `..` is reported and skipped, never copied.

1. **Source map.** A saved level with no unsaved changes is exported from its file. Otherwise `MainWindow.export_game_package` writes the current level to a temporary `maps/export_temp_<random>.json`, exports that, and deletes it when the export panel closes; the entry map inside the package then carries that temporary name.
2. **Maps.** Starting from the current map, `_collect_map_dependencies` follows every level change recursively. On each brush and entity it reads the first non-empty string among the keys `MAP_KEYS` = `target_map`, `map`, `next_map`, `next_level`, `target_level`, `level_name`, `map_name` (in `properties` or on the record itself), appends `.json` if missing, and looks for the file in `<root>/maps/`, then `<root>/`, then beside the referring map. The candidate must lie inside the project root. An absolute name is reported as `Skipped map outside the project`; a map that cannot be found as `Missing dependency: map ...`.
3. **Archive names for maps.** A map inside `<root>/maps/` keeps its path relative to the project root (sub-folders are preserved, so authored references still resolve). Any other map is stored as `maps/<basename>`. A name collision is resolved by appending `_1`, `_2`, ... The current map is named first.
4. **Cutscenes.** Every `cutscene_file` property (`CUTSCENE_KEY`) is resolved against the project root and must lie inside `cutscenes/`. The cutscene is stored at its project-relative path, and the assets named by the `definition` of each row of its `actors` list are added to the asset set.
5. **Referenced assets.** `player/runtime/package_assets.py: map_assets` walks each map document and collects every string value of a `textures` object, plus every non-empty string (not a `data:` URI) stored under one of `ASSET_KEYS` anywhere in the document: `texture`, `texture_path`, `sprite_2d`, `custom_idle`, `custom_shoot`, `custom_dead`, `model_path`, `mesh`, `sound_file`, `sound`, `audio`, `sprite_path`, `collect_custom_sprite`, `world_sprite`, `hud_sprite`, `muzzle_flash`, `fire_texture`, `orb_texture`, `custom_gif`.
6. **Implicit stock assets.** If any exported map has at least one entity, everything under `assets/sprites/`, `assets/textures/effects/` and `assets/sounds/` is included (monster states, weapons and built-in sounds are not named in the map). If any exported map has `terrain_data`, everything under `assets/textures/` is included.
7. **Companion files.** Each asset's bytes are scanned by `companion_assets`: an `.obj` adds its `mtllib` files; an `.mtl` adds the textures of its `map_*`, `bump`, `disp`, `decal` and `norm` statements (options parsed by `engine.obj_loader.OBJLoader._parse_texture_map`); a `.gltf`/`.glb` adds its external `buffers` and `images` URIs (`data:` URIs are skipped). Companion paths are resolved relative to the referring file; one that starts with `/` or contains `:` raises `Model companion must be project-relative`, which fails the export. Companions are scanned in turn, so an OBJ brings its MTL and the MTL brings its textures.
8. **Where assets are read from.** `ProjectAssets` indexes the members of every `assets/<category>.fiopak` and then every loose file under `assets/` (excluding `.py`, `.pyc` and `.fiopak`); a loose file overrides an archive member of the same path. See [name resolution](#name-resolution) for how a reference is matched.
9. **Writing.** The archive is assembled in a temporary file beside the destination (`engine.fileio.atomic_output`) and moved into place only when complete, so a failed export never damages an existing package. Order: `metadata.json`, maps, cutscenes (sorted), assets (sorted).

Unresolvable references do not fail the export. They are returned in `errors` as `Missing asset: ...`, `Skipped asset outside the project: ...`, `Missing dependency: map ...`, `Skipped map outside the project: ...`, `Missing cutscene: ...`, `Skipped cutscene outside cutscenes/: ...`, `Could not read ...` or `Not a map document: ...`. On a successful export `MainWindow._run_export` shows only "Export successful!"; the list is displayed (first five lines) only when the export fails. `player/tools/verify_package.py` (below) reports missing assets in a finished package.

## What a reader refuses

| Check | Where | Limit / rule |
| --- | --- | --- |
| Not a ZIP, file missing | `FioPackage.open` | `PackageError` |
| Plugin code | `FioPackage.__init__` → `_is_plugin_payload` | Any member that, as written or after resolving `..`, is `plugins` or starts with `plugins/` (compared case-insensitively): `Bundled plugins are not permitted in .fiopak archives; install required plugins separately.` |
| Corrupt manifest | `FioPackage._load_manifest` | `PackageError` |
| No map | `FioPackage.start_map_path` | `PackageError` |
| Manifest or map too large | `FioPackage._read_raw`, `PackageSession.load_json` | `MAX_DOCUMENT_BYTES` = 64 MiB per document |
| One asset too large | `FioPackage.read_asset`; `PackageSession.__init__` | `MAX_ASSET_ENTRY_BYTES` = 128 MiB. The player returns `None` for that asset; the editor refuses the whole package (`Package file too large`). |
| Assets too large in total | same | `MAX_TOTAL_ASSET_BYTES` = 512 MiB. The player counts each resolved entry once as it is read and returns `None` past the budget; the editor sums every member's declared size when the package opens (`Package expands past the size limit`). |
| Too many members | `PackageSession.__init__` (editor only) | `PackageSession.MAX_ENTRIES` = 20000 |
| Unsafe member name | `PackageSession.__init__` (editor only) | A file member whose name is absolute, has a drive/scheme colon in its first component, contains a `..` component, or is not already in normalised form: `Unsafe path in package: <name>` |
| Start map missing | `PackageSession.__init__` (editor only) | `FileNotFoundError` |

All size checks use the sizes declared in the ZIP directory, before anything is decompressed. The constants live in `player/runtime/fiopak.py` and its editor-side copy `player/fiopak.py`.

## How the editor plays a package

`MainWindow.play_package_from_path(file_path)` (`editor/main_window.py`):

1. Asks about unsaved changes.
2. Builds an `editor/package_session.py: PackageSession`, which runs the checks above and records the member names and the start map. The archive is opened for each read and never held open; it is never written.
3. Loads the start map with `PackageSession.load_json` and applies it through `MainWindow._apply_level_data`. `MainWindow.file_path` is set to `None` first, so the level is untitled: Save goes through Save As and can never overwrite the package.
4. Stores the session as `MainWindow._package` and calls `engine.asset_archives.set_package(session.path, session.names)`, which makes the package's `assets/...` members available to every asset loader (below).
5. Enters kiosk mode, unless `[Kiosk] launch_in_editor` is set.

While the session is open:

* A level change (`LevelChanger`, or the `map` console command) is looked up in the package first: `MainWindow._package_map_path(relative)` → `PackageSession.member`, then `_load_package_map`. A name the package does not hold falls through to the project's own files.
* Play hands the session to the logic thread as `LogicThread.package`; `engine/cutscene_runtime.py: CutsceneRuntime._package_cutscene` reads a cutscene from the package's `cutscenes/` before the project's.
* The session ends (`MainWindow._close_package`) when a map is opened from disk, a new map is created, another package is opened, or the window closes. There is nothing to clean up.

`PackageSession` API: `path`, `start_map`, `names` (frozenset of file members), `member(relative_path)` (the exact member a relative path names, or `None` when it is absent, absolute or climbs out), `read(member)`, `load_json(member)`. `FioPackage` implements the same `member` / `load_json` pair, which is all the shared engine calls on `logic.package`.

## How the Fio Player plays a package

`player/runtime/fiopak.py: FioPackage` streams every entry out of the ZIP:

```python
from player.runtime.fiopak import FioPackage

with FioPackage.open("game.fiopak") as pak:     # or FioPackage.from_bytes(data)
    level = pak.load_start_map()
    png = pak.read_asset("floor.png")
```

| Member | Behaviour |
| --- | --- |
| `open(path)` / `from_bytes(data, source="<bytes>")` | Opens from disk or from memory. Raises `PackageError` for a missing file, a bad ZIP, or a `plugins/` payload. |
| `metadata`, `title`, `source`, `required_plugins` | Manifest access. |
| `namelist()` | Every entry name, sorted. |
| `list_maps()` | Sorted `.json` members, excluding the manifest and anything under `assets/` or `cutscenes/`. |
| `start_map_path()` | `map_path` / `start_map` / `main_map` from the manifest if that member exists, else a map with the same base name, else the first map. Raises `PackageError` when the package has no map. |
| `load_map(archive_path)`, `load_start_map()` | Parsed map; must be a JSON object. |
| `resolve_map(reference, current="")` | Resolves a level transition inside the archive: the name as written (`.json` appended if missing), `maps/<name>`, the directory of the current map, then a unique base-name match. Raises `PackageError` when missing or ambiguous. Never touches the host disk. |
| `read_asset(path)`, `open_asset(path)`, `read_text(path)`, `has_asset(path)` | Asset access. `None` (or `False`) when the asset cannot be found or exceeds a limit. Text is decoded as UTF-8 (BOM tolerated), then Latin-1. |
| `member(relative_path)`, `load_json(member)` | The exact-name pair used by the shared engine (cutscenes). |

A `FioPackage` is not thread-safe: one `ZipFile` handle backs every read.

`player/fiopak.py` is the copy of this reader that the editor's `PackageSession` and `tests/persistence/` use. It lacks `resolve_map`, `member` and `load_json`, and its `list_maps` does not exclude `assets/` and `cutscenes/`.

Running a package with the player from a source checkout, and checking one:

```bash
python -m player.main path/to/game.fiopak [--width 1280] [--height 720] [--fps 60] [--fullscreen | --windowed | --borderless]
python -m player.tools.verify_package path/to/game.fiopak
```

## Name resolution

All package and export lookups are **case-sensitive** dictionary lookups on member names; a reference whose letter case differs from the stored member does not match at the exact step and can only be found by a later step that happens to match.

| Lookup | Order (first hit wins) |
| --- | --- |
| Exporter, asset reference → project file (`ProjectAssets.resolve`) | Rejected outright if it starts with `/`, contains `:` or has a `..` component. Then: the normalised path as written; `assets/<path>`; `assets/<folder>/<path>` for `textures`, `models`, `sounds`, `music`, `sprites`, `fonts`, `materials`; finally a base-name match across all sources, used only when exactly one file has that base name. |
| Player, asset in a package (`FioPackage._resolve`) | The path as given; the same path with its `assets/` prefix removed, or (when it has none) added; when the reference has a directory part, its base name under `assets/`, `assets/textures/`, `assets/models/`, `assets/sounds/`, `assets/sprites/`, `assets/materials/`; finally a base-name match over the whole archive (the first member in sorted order with that base name). |
| Player, map in a package (`FioPackage.resolve_map`) | As listed in the table above. |
| Editor, map or cutscene in a played package (`PackageSession.member`) | Exact member name only, after normalising separators. |
| Editor, asset in a played package (`engine.asset_archives._find`) | The loose file at that path if one exists; then a category archive member; then the package member `assets/...` with the same project-relative path. Archive and package members are matched exactly first and then by a case-folded comparison, as a Windows file system would. |

Map references therefore do not need rewriting when a level is packaged.

In the editor, the Play-mode sound loader (`engine/view_audio.py: ViewAudio._get_sound_instance`) reads sounds from `assets/sounds.fiopak` / `assets/music.fiopak` (authoritative when the archive exists) or from the loose folders; it does not consult a played package.

## Plugins

A package cannot carry plugin code (see the table above); because the editor opens a package through the same reader, it refuses such a package too. A world that needs a plugin relies on that plugin being installed on the host: plugin entities in a map enable their plugin on load (`PluginManager.auto_enable_for_map`), and the manifest's `plugins` list or a map's `required_plugins` names any others for the player.

# Category asset archives

`engine/asset_archives.py` lets an installation ship its stock assets as one archive per category instead of thousands of loose files. `ASSET_CATEGORIES`:

| Archive | Contents |
| --- | --- |
| `assets/editor.fiopak` | Image files directly in `assets/` (toolbar icons, application icons, splash) |
| `assets/sprites.fiopak` | `assets/sprites/` |
| `assets/textures.fiopak` | `assets/textures/` and `assets/noise_3d.bin` |
| `assets/models.fiopak` | `assets/models/` |
| `assets/fonts.fiopak` | `assets/fonts/` |
| `assets/music.fiopak` | `assets/music/` |
| `assets/sounds.fiopak` | `assets/sounds/` |

The repository ships `fonts.fiopak`, `music.fiopak` and `sounds.fiopak`; the other categories are loose files.

Member rules (`category_member`): names are project-relative (`assets/<category>/...`), use forward slashes, and contain no empty, `.` or `..` component and no `:`. The suffix must be a known data type (`.png .jpg .jpeg .gif .bmp .ico .icns .ppm .pbm .pgm .pnm .webp .tga .tif .tiff .dds .ktx .ktx2 .ttf .otf .obj .mtl .glb .gltf .bin .json .txt .md .wav .ogg .mp3`) or absent; an `editor` member must sit directly in `assets/` and be one of the first eleven (image) types. An archive with a member outside its category, a symbolic link, a duplicate name, more than `MAX_ENTRIES` = 10000 entries, an entry over `MAX_ENTRY_BYTES` = 256 MiB or a total over `MAX_TOTAL_BYTES` = 512 MiB is rejected as a whole (`[Assets] Cannot read <name>: <reason>`) and startup continues with the loose files.

`prepare_asset_archives(root_dir)` indexes the archives and writes nothing. It is called from `main.py` before the splash screen and again from `MainWindow.__init__`; repeated calls only `stat` each archive and re-index one whose mtime or size changed. An archive is opened for each read and never held open, so `tools/pack_assets.py` can replace one while the editor runs.

Loaders ask for an asset by the path they have always used:

| Function | Returns |
| --- | --- |
| `asset_bytes(path)` | The loose file's bytes if it exists, else the archive (or played package) member's, else `None`. |
| `asset_source(path)` | The path itself for a loose file, an `io.BytesIO` of the member otherwise, `None` if neither (for Pillow and similar). |
| `asset_exists(path)`, `asset_isdir(path)` | Loose or archived. |
| `asset_listdir(path)` | Sorted names of the loose and archived children (`.gitkeep` removed). |
| `asset_files(path, suffixes=None)` | Every file under the folder, recursively, loose or archived. |
| `asset_member(path)` | The `assets/...` member name for a path, or `None` if it is outside the project's `assets/`. |
| `set_package(path, names=())` | Adds a played game package's `assets/...` members after the loose files and category archives; `None` removes it. |

Qt images, icons and fonts go through `engine/asset_qt.py` (`load_pixmap`, `load_icon`, `add_application_font`). A loose file always wins over an archive member, so loose files act as development overrides.

Audio is decoded straight from the ZIP through `engine/audio_archives.py` (`AudioArchiveReader`, `list_archive_audio`, `open_archive_audio`, `read_archive_audio`), which accepts only `.wav`, `.ogg` and `.mp3` members under the given asset root and caps a member at `MAX_AUDIO_BYTES` = 256 MiB. For sounds and music an existing archive is authoritative: the loose folder is used only when the archive file is absent.

## `tools/pack_assets.py`

Builds the category archives from the loose files.

```text
python tools/pack_assets.py [--root PROJECT] [category ...]
```

| Argument | Default | Meaning |
| --- | --- | --- |
| `--root PROJECT` | The repository containing the script | Project root (the directory that holds `assets/`). |
| `category ...` | All categories | Any of `editor`, `sprites`, `textures`, `models`, `fonts`, `music`, `sounds`. |

Behaviour of `pack_category(root, category)`:

* Collects the loose files that are valid members of the category (for `editor`, only files directly in `assets/`; for `textures`, `assets/noise_3d.bin` as well). A symbolic link or a file resolving outside `assets/` raises `asset outside project`.
* A category with no loose files keeps its existing archive untouched and prints `<name>: no loose files; existing archive preserved`.
* Otherwise the existing archive's members are read first and the loose files are laid over them, so repacking a partial set of loose overrides does not drop archive-only members. To remove an asset, remove both the loose file and its archive entry.
* The archive is written deterministically: members sorted by name, timestamp fixed at 1980-01-01, mode `0644`, `ZIP_DEFLATED` at level 9. Every payload is read back and compared before the new archive replaces the old one.
* Prints `<name>: <n> files packed` per category and exits with status 0.
