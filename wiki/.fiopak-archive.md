> Applies to Fio 3.1.0.0611 (CANARY).

`.fiopak` is Fio's archive format: an ordinary ZIP file with a fixed member layout. It is used for two different things, which share the extension and the "data only, project-relative paths" rule but have different contents and readers:

* a **game package** (`packages/<title>.fiopak`): one or more maps, the cutscenes and assets they reference, and a manifest. Exported by the editor and played by the editor or by the standalone [Fio Player](https://github.com/ViciousSquid/Fio/wiki/Fio-Player-(Android));
* a **category asset archive** (`assets/<category>.fiopak`): the engine's own stock assets for one category, read at startup.

Neither kind may contain code. A game package with any member under a top-level `plugins/` directory is rejected.

# Game packages

## Using them

* **Tools > Export Game Package...** (`Ctrl+Shift+E`) opens the export form in the Properties dock. Fill in **Package Title** (required), **Author**, **Version** (default `1.0.0`) and **Description**, press **Export...** and choose a file; the dialog starts in `packages/` with the name `<title>.fiopak`.
* **Tools > Play Game Package...** asks for a `.fiopak` and plays it. The [Asset Browser](https://github.com/ViciousSquid/Fio/wiki/Asset-Browser)'s Maps tab can be switched to list `packages/`; double-clicking a package does the same.
* A package is launched in kiosk (fullscreen play) mode unless `[Kiosk] launch_in_editor` is true (Settings > Play Modes > "Launch packages in editor mode"), in which case its start map is opened in the editor without starting Play.

## Container and layout

The archive is written with `zipfile.ZIP_DEFLATED`. Member names use forward slashes and are relative to the project root.

```text
metadata.json                 manifest
maps/<name>.json              the entry map and every map reachable from it
cutscenes/<name>.json         cutscenes named by the maps
assets/textures/...           referenced assets, at their project-relative paths
assets/models/...
assets/sprites/...
assets/sounds/...
```

### `metadata.json`

Written by `PackageExporter.export` as JSON with a 2-space indent.

| Key | Type | Written by the exporter | Meaning |
| --- | --- | --- | --- |
| `title` | string | Yes | Package title. The reader returns `"Untitled"` when absent. |
| `author` | string | Yes | |
| `version` | string | Yes | Free text; `1.0.0` by default. |
| `description` | string | Yes | |
| `map_path` | string | Yes | Archive path of the entry map, for example `maps/Office_Corridor.json`. Always set by the exporter to the path the current map was stored under. |
| `plugins` | list of strings | No | Names of plugins that must already be installed. Read by `FioPackage.required_plugins`; the Fio Player refuses to start a world whose required plugin is not installed. |

Readers also accept the manifest under the older name `manifest.json`, and the entry map under the keys `start_map` or `main_map`. A package with no manifest is valid: the entry map is then the first map in sorted order.

## How the exporter chooses the contents

`editor/package_exporter.py: PackageExporter.export(output_path, metadata, current_map_path, parent_widget=None)` returns `(success, errors)`. Everything it writes comes from inside the project: a map or asset reference that is absolute or climbs out with `..` is reported and skipped, never copied.

1. **Source map.** A saved level with no unsaved changes is exported from its file. Otherwise `MainWindow.export_game_package` writes the current level to a temporary `maps/export_temp_<random>.json`, exports that, and deletes it when the export panel closes; the entry map inside the package then carries that temporary name.
2. **Maps.** Starting from the current map, `_collect_map_dependencies` follows every level change recursively. On each brush and entity it reads the first non-empty string among the keys `target_map`, `map`, `next_map`, `next_level`, `target_level`, `level_name`, `map_name` (in `properties` or on the record itself), appends `.json` if missing, and looks for the file in `<root>/maps/`, then `<root>/`, then beside the referring map. A map that cannot be found is reported as `Missing dependency`.
3. **Archive names for maps.** A map inside `<root>/maps/` keeps its path relative to the project root (sub-folders are preserved, so authored references still resolve). Any other map is stored as `maps/<basename>`. A name collision is resolved by appending `_1`, `_2`, ...
4. **Cutscenes.** Every `cutscene_file` property is resolved against the project root and must lie inside `cutscenes/`. The cutscene is stored at its project-relative path, and the assets named by the actors it spawns are added to the asset set.
5. **Referenced assets.** `player/runtime/package_assets.py: map_assets` walks each map document and collects every string in a `textures` object, plus every non-empty string (not a `data:` URI) stored under one of these keys anywhere in the document: `texture`, `texture_path`, `sprite_2d`, `custom_idle`, `custom_shoot`, `custom_dead`, `model_path`, `mesh`, `sound_file`, `sound`, `audio`, `sprite_path`, `collect_custom_sprite`, `world_sprite`, `hud_sprite`, `muzzle_flash`, `fire_texture`, `orb_texture`, `custom_gif`.
6. **Implicit assets.** If any exported map has at least one entity, everything under `assets/sprites/`, `assets/textures/effects/` and `assets/sounds/` is included (monster states, weapons and built-in sounds are not named in the map). If any exported map has `terrain_data`, everything under `assets/textures/` is included.
7. **Companion files.** Each asset is read and scanned by `companion_assets`: an `.obj` adds its `mtllib` files, an `.mtl` adds its `map_*`/`bump`/`disp`/`decal`/`norm` textures, and a `.gltf`/`.glb` adds its external `buffers` and `images` URIs. Companion paths are resolved relative to the referring file and must be project-relative.
8. **Where assets are read from.** `ProjectAssets` indexes the members of every `assets/<category>.fiopak` and then every loose file under `assets/` (excluding `.py`, `.pyc` and `.fiopak`); a loose file overrides an archive member of the same path. A reference is resolved in this order: the path as written; `assets/<path>`; `assets/<folder>/<path>` for `textures`, `models`, `sounds`, `music`, `sprites`, `fonts`, `materials`; finally a unique base-name match across all sources. An ambiguous base name does not resolve.
9. **Writing.** The archive is assembled in a temporary file beside the destination (`engine.fileio.atomic_output`) and moved into place only when complete, so a failed export never damages an existing package.

Unresolvable references do not fail the export. They are returned in `errors` as `Missing asset: ...`, `Skipped asset outside the project: ...`, `Missing dependency: map ...`, `Missing cutscene: ...` or `Skipped cutscene outside cutscenes/: ...`. On a successful export `MainWindow._run_export` shows only "Export successful!"; the list is displayed only when the export fails. `player/tools/verify_package.py` (below) reports missing assets in a finished package.

## How the editor opens a package

`MainWindow.play_package_from_path(file_path)`:

1. Asks about unsaved changes.
2. `_extract_package` opens the archive with `player.fiopak.FioPackage` first. This applies the reader's rules (valid ZIP, no `plugins/` payload, manifest and map size limits) and yields the entry map path from the manifest.
3. `_safe_extract_zip` extracts the whole archive into a fresh `fio_package_*` temporary directory, after checking every member: at most 20,000 entries (`MainWindow.MAX_PACKAGE_ENTRIES`), no member resolving outside the destination, no member over 128 MiB, and no more than 512 MiB in total (declared sizes).
4. The entry map is loaded as an untitled level with no unsaved changes. The level's file path is deliberately left empty so that Save goes through Save As and can never overwrite the package or its extraction.
5. The extraction directory becomes `MainWindow._package_level_dir`. While it is set, a level change (`LevelChanger`, or the `map` console command) looks for the named map inside the extraction first, and Play looks up cutscenes there (`LogicThread.package_root`). Opening a map from disk, creating a new map or opening another package ends the package session; the temporary directory is removed when it is replaced.
6. Play starts in kiosk mode unless `[Kiosk] launch_in_editor` is set.

In the editor only maps and cutscenes are taken from the extracted package. Textures, models, sprites and sounds are loaded through the editor's normal asset paths, that is from the installation's own `assets/` folder.

## How the Fio Player opens a package

The player never extracts. `player/runtime/fiopak.py: FioPackage` streams every entry out of the ZIP:

```python
from player.runtime.fiopak import FioPackage

with FioPackage.open("game.fiopak") as pak:     # or FioPackage.from_bytes(data)
    level = pak.load_start_map()
    png = pak.read_asset("floor.png")
```

| Member | Behaviour |
| --- | --- |
| `open(path)` / `from_bytes(data, source="<bytes>")` | Opens from disk or from memory. Raises `PackageError` for a missing file, a bad ZIP, or a `plugins/` payload. |
| `metadata`, `title`, `source`, `required_plugins` | Manifest access. |
| `list_maps()` | Sorted `.json` members, excluding the manifest and anything under `assets/` or `cutscenes/`. |
| `start_map_path()` | `map_path` / `start_map` / `main_map` from the manifest if that member exists, else a map with the same base name, else the first map. Raises `PackageError` when the package has no map. |
| `load_map(archive_path)`, `load_start_map()` | Parsed map; must be a JSON object. |
| `resolve_map(reference, current="")` | Resolves a level transition inside the archive: the name as written, `maps/<name>`, the directory of the current map, then a unique base-name match. Never touches the host disk. |
| `read_asset(path)`, `open_asset(path)`, `read_text(path)`, `has_asset(path)` | Asset access. Returns `None` when the asset cannot be found or exceeds a limit. |

Asset resolution (`_resolve`), first hit wins: the path as given; the same path with an `assets/` prefix removed or added; the base name under `assets/`, `assets/textures/`, `assets/models/`, `assets/sounds/`, `assets/sprites/`, `assets/materials/`; finally a base-name match over the whole archive (the first in sorted order). Map references therefore do not need rewriting when a level is packaged.

Limits, checked against the ZIP's declared sizes before decompression:

| Constant | Value | Applies to |
| --- | --- | --- |
| `MAX_ASSET_ENTRY_BYTES` | 128 MiB | One asset. |
| `MAX_TOTAL_ASSET_BYTES` | 512 MiB | All assets read through one `FioPackage`. Each resolved entry is cached and counted once. |
| `MAX_DOCUMENT_BYTES` | 64 MiB | The manifest and each map. |

A `FioPackage` is not thread-safe: one `ZipFile` handle backs every read.

`player/fiopak.py` is a second copy of this reader used by the editor (`_extract_package`) and by `tests/persistence/`. It lacks `resolve_map`, and its `list_maps` does not exclude `assets/` and `cutscenes/`.

Running a package with the player from a source checkout, and checking one:

```bash
python -m player.main path/to/game.fiopak
python -m player.tools.verify_package path/to/game.fiopak
```

`verify_package` opens the package with the player's reader, resolves every asset every map references (including model companions), steps each map once in the shared simulation, and prints `PASS: <n> maps, <n> referenced assets, ...` or `FAIL: <reason>` (exit status 1).

## Plugins

A package cannot carry plugin code. `FioPackage.__init__` raises `PackageError("Bundled plugins are not permitted in .fiopak archives; install required plugins separately.")` if any member path, as written or after resolving `..`, is `plugins` or starts with `plugins/` (case-insensitive). Because the editor opens a package with the same reader before extracting it, the editor refuses such a package too. A world that needs a plugin relies on that plugin being installed on the host: plugin entities in a map enable their plugin on load, and the manifest's `plugins` list names any others.

# Category asset archives

`engine/asset_archives.py` lets an installation ship its stock assets as one archive per category instead of thousands of loose files.

| Archive | Contents |
| --- | --- |
| `assets/editor.fiopak` | Image files directly in `assets/` (toolbar icons, application icons, splash) |
| `assets/sprites.fiopak` | `assets/sprites/` |
| `assets/textures.fiopak` | `assets/textures/` and `assets/noise_3d.bin` |
| `assets/models.fiopak` | `assets/models/` |
| `assets/fonts.fiopak` | `assets/fonts/` |
| `assets/music.fiopak` | `assets/music/` |
| `assets/sounds.fiopak` | `assets/sounds/` |

Member rules (`category_member`): names are project-relative (`assets/<category>/...`), use forward slashes, and contain no empty, `.` or `..` component and no `:`. The suffix must be a known data type (images, fonts, `.obj`/`.mtl`/`.glb`/`.gltf`/`.bin`, `.json`/`.txt`/`.md`, `.wav`/`.ogg`/`.mp3`) or absent. An archive with a member outside its category, a symbolic link, a duplicate name, more than 10,000 entries, an entry over 256 MiB or a total over 512 MiB is rejected as a whole.

`prepare_asset_archives(root_dir)` runs at startup (before the splash screen, and again from `MainWindow.__init__`):

* For every category except `sounds` and `music`, each member whose loose file does not already exist is written to its project-relative path. An existing loose file is never overwritten, so loose files act as development overrides. An archive-only installation therefore needs a writable `assets/` directory.
* `sounds.fiopak` and `music.fiopak` are not extracted. Audio is decoded straight from the ZIP through `engine/audio_archives.py` (`AudioArchiveReader`, `list_archive_audio`, `open_archive_audio`, `read_archive_audio`), which accepts only `.wav`, `.ogg` and `.mp3` members under the given asset root and caps an eagerly read member at 256 MiB.
* A bad archive is reported (`[Assets] Cannot prepare <name>: <reason>`) and skipped; startup continues with whatever loose files exist. An unchanged archive (same mtime and size) is not re-read on later calls.

## `tools/pack_assets.py`

Builds the category archives from the loose files.

```text
python tools/pack_assets.py [--root PROJECT] [category ...]
```

| Argument | Default | Meaning |
| --- | --- | --- |
| `--root PROJECT` | The repository containing the script | Project root (the directory that holds `assets/`). |
| `category ...` | All categories | Any of `editor`, `sprites`, `textures`, `models`, `fonts`, `music`, `sounds`. |

Behaviour of `pack_category(root, category)`:

* Collects the loose files that are valid members of the category (for `editor`, only files directly in `assets/`; for `textures`, `assets/noise_3d.bin` as well).
* A category with no loose files keeps its existing archive untouched and prints `<name>: no loose files; existing archive preserved`.
* Otherwise the existing archive's members are read first and the loose files are laid over them, so repacking a partial set of loose overrides does not drop archive-only members. To remove an asset, remove both the loose file and its archive entry.
* The archive is written deterministically: members sorted by name, timestamp fixed at 1980-01-01, mode `0644`, `ZIP_DEFLATED` at level 9. Every payload is read back and compared before the new archive replaces the old one.
* Prints `<name>: <n> files packed` per category and exits with status 0.
