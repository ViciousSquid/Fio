## Analysis

Subsystems affected: **plugin architecture, Benchmark, Tidy (Phase G and H)**.

**502 "Refactor Benchmark into optional developer plugin"** — the payoff for
Phase A's 308 commits. `editor/benchmark.py`, `benchmark_manager.py` and
`tests/performance/fio_benchmark.py` become `plugins/benchmark/`. The editor's
hard-coded Tools-menu entry and console command are removed; Benchmark is
discovered, enabled and dispatched like any other plugin.
Verified at HEAD: `editor/main_window.py`'s net diff retains **no** benchmark
code, and `editor/console_commands.py` routes through
`mgr.dispatch_console_command(cmd, args, lt, main_window=..., play_mode=...)`.
The `main_window=` kwarg is new — it widens the plugin console API's reach from
the logic thread to the whole editor window. Recorded in architecture.md.

* 503 "Avoid unrelated SysMon line-ending churn"; 504/506/507 plugin API docs;
  505 moved worker path; 508 "Fix plugin Tools menu owner"; 509 "Open Benchmark
  from Plugins enable toggle"; 510 missing `html` import; 511/512 plugin
  versions in the About dialog rather than the menu; **513 "Fix Benchmark plugin
  migration"**.

* **514/515 "plugins: add generic map migration/activation hooks" / "support map
  migration and core-entity activation hooks"** — `FioPlugin.migrate_map_data`,
  `PluginManager.migrate_map_data`, and calls from `EditorState.load_from_data`
  and `PlayerPluginHost`. Built specifically so a plugin can convert its own
  legacy records before core deserialisation. **Deleted at 534–537.**

* 516 "prop: allow gameplay plugins to consume a drop" — the
  `_prop_drop_interceptor` hook on the logic object, letting Tidy consume a drop
  as a placement while core Prop keeps pickup/carry/ordinary drop.
  **Fragility noted:** on interception `PropSession._carry` `return`s *without*
  clearing `self.held`; it relies on the interceptor doing so (Tidy's `_place`
  does). An interceptor that consumes a drop without clearing `held` leaves the
  prop welded to the player. Recorded in architecture.md.

* **517 "tidy: remove duplicate TidyObject entity"** — the `TidyObject` class
  (map type `tidyobject`) is deleted. 518/519 delegate Tidy's interaction and
  physics to core Prop and extend it with a `tidy_category` property instead.
  This is the right architecture — one Prop primitive, gameplay as metadata.
  **But it makes every 2.4.2 Tidy map's objects unloadable unless the migration
  from 514/515 survives. It did not (chunk 27).**

* 520 "editor: run plugin map migrations before entity deserialization" — the
  ordering that makes migration work at all.
