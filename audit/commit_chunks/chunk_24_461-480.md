## Analysis

Subsystems affected: **Prop representation, property editor tabs, triggers
(Phase F opens)**.

* 460–464: Model collision-shape selector kept as a dedicated control; Prop
  physics properties move to a **dedicated Physics tab** (463/464).
* **465–473: explicit Prop render mode.** What existed before: Prop chose
  between model and billboard *implicitly* — `model_path` if set, else
  `sprite_path` (baseline.md §1). Now `render_mode` is an authored property
  (`'model'` / `'billboard'`) and 473 makes the choice "authoritative".
  471 loads billboard textures per Prop instance; `qt_game_view` gains a
  `Prop` branch in `update_instance_textures` and in the instance-texture
  cache key.
  **Compatibility: this is a data-format addition with an implicit default.**
  A 2.4.2 Prop with a `sprite_path` and no `model_path` rendered as a billboard;
  in 2.5 it gets `render_mode` defaulting to `'model'`. Whether such a prop
  still billboards depends on the default applied at load. Recorded in
  compatibility.md as the item most worth a targeted check on real maps.
* **466 "Keep plugin Prop render mode in sync"** — an explicit acknowledgement
  that `editor.things.Prop` and `plugins.entitybase.Prop` must not drift. This
  is the duplication the brief asks about, being patched by hand rather than
  removed. (The published snapshot later solves it properly with
  `engine/prop_entity.py`; see architecture.md.)
* 474 "Fix prop physics position sync on pickup/drop" — the physics body and
  the entity position had diverged across a pickup.

* **475 "Add physics console controls and trigger detection filters"** opens
  Phase F. Adds `phys_gravity`, `phys_timescale`, `phys_friction`,
  `phys_damping`, `phys_sleep`, `phys_info`, `phys_reset` to the editor console,
  reaching `logic_thread._physics_world` directly.
  **Threading concern:** these mutate `PhysicsWorld` scalars and call
  `wake_all()` from the **Qt main thread** while the logic thread is stepping.
  Scalar writes are GIL-atomic, but `wake_all()` touches the awake array while
  `step()` may be masking on it. Recorded in architecture.md; not observed to
  fail, and the controls are developer tools.
* 476 "Wire trigger activators through I/O" — `fire_output` gains
  `activator_entity`, so the entity that touched a trigger propagates through
  every I/O hop including delayed ones. Its test was added to a module that
  could not be collected, so it had never run (see testing.md); it passes now.
* **477 "Batch trigger filters and poll non-player occupants at 1 Hz"** — the
  trigger rewrite begins. 478/479 repair its tests.
* 480 "Update trigger I/O activator descriptions".
