## Analysis

Subsystems affected: **physics ownership move, then vectorisation**.

**The cleanest transformation in the range.**

What existed before → what replaced it:

* **422/423 "Move dynamic body simulation into engine physics" / "Route dynamic
  bodies through engine physics world"** — `PhysicsWorld` and `PhysicsBody` are
  born in `engine/physics.py`. Dynamic-body simulation leaves `PropSession`.
* **425 "Keep PropSession focused on interaction only"** — `PropSession` is
  reduced to pickup / carry / drop. The baseline's `_simulate` (vertical-only
  gravity with a `raycast_down` floor test) is gone; the engine owns motion.
* **427/428 "Remove Prop-specific dynamic collision naming"** ×2 — the engine's
  physics stops mentioning Prop. Correct: a dynamic body is an engine concept,
  and Prop is merely its first client. This is the migration being *finished*
  rather than left half-done, which is notable in this history.
* 424 "Rebuild engine physics bodies when model collision toggles";
  432/433/434 keep dynamic physics independent of the model-collision toggle.
* 426 "Use engine physics body markers in player collision" — the player now
  recognises dynamic bodies.
* 431/436 resolve floor contact using the shape offset and align the body-centre
  semantics. This is the `offset` / `half` distinction that later matters for
  the restored `PhysicsBody.size` accessors.

**439–443: the batched NumPy rewrite.** `PhysicsWorld` moves from a list of
`PhysicsBody` objects to **structure-of-arrays**: `_position`, `_velocity`,
`_half`, `_offset`, `_mass`, `_friction`, `_damping`, `_gravity`,
`_angular_velocity`, `_solid`, `_physics_enabled`, `_awake`, `_kinematic`.
440 masks integration to awake bodies only; 441 reduces Python overhead in
collision queries by caching per-cell static AABB arrays; 442 fixes cached
empty collision groups; 443 documents it.

**CONFIRMED DEFECT (fixed in this audit): the SoA rewrite kept the arrays but
dropped `PhysicsBody`'s read side.** Before 439 the handle exposed `size`,
`offset`, `gravity`, `friction`, `linear_damping`, `angular_velocity`, `solid`
and `brush`. After 439 only `velocity`, `mass`, `awake` and `kinematic`
survived. `tests/physics/test_dynamic_bodies.py` asserted `body.size` and
`body.offset` and could not pass. Restored as index-backed properties reading
the packed row; `size` keeps its pre-rewrite full-extent meaning and
`half_extents` exposes the half-size the maths uses. See fixes.md.

**Second defect from the same commit: `PhysicsBody._index` did not pack.**
Registration only queues a row; the index exists after `_pack()`. Every handle
accessor therefore returned not-found defaults (zeros) between `register_body`
and the first `step`, silently. Now packs on demand (`_pack` early-outs unless
dirty, so the steady-state path is unchanged).

Architectural concern: `PhysicsWorld._rebuild_static_cells` reads
`self.spatial_grid.cells` — the grid's **internal dict**, not its query API
(`get_potential_colliders`). `_batch_static_collision` likewise reads
`spatial_grid.cell_size`. The vectorisation bought speed by coupling
`PhysicsWorld` to `SpatialGrid`'s data layout. This is exactly what broke the
test stubs, which were written against the public API.
