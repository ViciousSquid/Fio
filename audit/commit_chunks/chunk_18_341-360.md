## Analysis

Subsystems affected: **renderer (major)** — `renderer_core.py`, `renderer_F.py`,
`render_cull.py`, `logic_thread.py`, `qt_game_view.py`, `threaded_game_state.py`.

**Phase C: the render hot path is vectorised. This is the first of the two
genuine architectural transformations in the range.**

What existed before → what replaced it:

* **Per-frame model classification** → cached classification.
  342/343/344 ("Remove renderer model cache and classification hot-path
  overhead", "Finish zero-overhead model classification path", "Remove
  per-frame model classification scans"). At baseline `_sort_objects` walked
  every Thing each frame doing `isinstance` tests to split sprites from models.
  342 also reduces `load_model` to a **single dict lookup** on the hot path,
  moving path normalisation to cache misses only and aliasing the authored
  spelling so later frames stay on the fast path. Good, targeted work.
* **Python distance/depth loops** → NumPy batches.
  345 ("Vectorize render distance output and depth sorting") adds
  `sort_by_distance` and `positions_out` to `render_cull`; 350 batches the
  renderer's cull and depth sort; 351 batches shadow-caster distance tests.
* **Per-frame list allocation** → reusable buffers.
  346/347/348 publish a reusable visible-brush position buffer through the
  render state; 352 aligns the position buffers with the object lists;
  363 restores reusable camera cull object buffers.
* **Recomputed model matrices** → cached transforms. 349 caches classification
  and model transforms; 362 caches normal matrices with them; 360 repairs the
  cached-matrix definition.

**353 "Preserve stable ordering in vectorized depth sort" is a real correctness
fix.** The first version did `np.argsort(d, kind="stable")[::-1]` for the
far-to-near pass — reversing a stable ascending sort reverses its *ties* too,
so equal-distance transparent surfaces drew in reverse authored order. Replaced
with `np.argsort(-d, kind="stable")`, which matches Python's own stable reverse
sort. **Verified at HEAD, and now pinned** by a new test
(`test_depth_sort_is_stable_across_equal_distances`).

* 355–359: five commits restoring CRLF line endings on the five engine files
  this phase rewrote. Whole-file rewrites; each was checked and none lost code.
* 354/361 add tests for the batched cull and strengthen the position-buffer test.

Potential regression — **checked and cleared**: `sort_by_distance` keeps two
implementations either side of `min_numpy_count=16`. A scene crossing that
threshold must not reorder. Nothing tested it. Verified empirically that the
two agree for counts 2–40 in both directions, and **added a boundary
equivalence test**. The one deliberate asymmetry is positionless objects: the
scalar path fail-opens, the batched path requires a row per object by
documented contract.

Performance: this is the chunk that actually earns its keep. The work is
correctly targeted at measured hot paths rather than blanket vectorisation.
Architectural concern: the renderer now depends on the *logic thread* to
publish correctly-aligned position buffers (`visible_brush_positions`,
`visible_thing_positions`). That is a new cross-thread data contract; 352
exists because the first version mis-aligned them.
