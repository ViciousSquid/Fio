## Analysis

Subsystems affected: **Tidy, plugin packaging, player host, map compatibility.**

**This chunk contains the most serious finding in the audit.**

* 521 "packaging: bundle plugins attached to core entities" — `.fiopak` must now
  ship a plugin that only *extends* a core entity, since Tidy no longer owns an
  entity type of its own.
* 522 "player: run core Prop interaction alongside plugins" — the standalone
  host gains a shared `PropSession`, so a core Prop is carryable in the player
  without any plugin. Correct parity work.
* 523–527: tests migrated from TidyObject to core Prop.
* 528–530, 541/542: docs de-TidyObject-ed.
* 531 "tidy: restore receptacle and goal I/O declarations" — the I/O
  declarations were lost in the entity rework and had to be put back.
* 532 "tests: keep Tidy smoke suite pytest-free".
* 533 "tidy: update Tidy_Test to core Prop format" — the shipped test map is
  rewritten from `tidyobject` to `prop` + `tidy_category`. Verified:
  2.4.2's `maps/Tidy_Test.json` has 42 `tidyobject`; 2.5's
  `plugins/tidy/Tidy_Test.json` has 42 `prop`.

### The regression: 534–540

Seven consecutive commits delete the migration and its coverage:

* 534 "plugins: remove unused map migration API" (`plugins/api.py`, −8)
* 535 "plugins: remove unused map migration orchestration" (`plugins/manager.py`, −17)
* 536 "editor: remove unused plugin map migration hook" (`editor/editor_state.py`, −9)
* 537 "player: remove unused plugin map migration call" (`player/plugin_host.py`, −5)
* 538 "tidy: remove obsolete legacy-map migration" (`plugins/tidy/plugin.py`, −31)
* 539/540 "tests: remove obsolete legacy migration coverage" (−31, −30)

The API was called "unused" because, *within the repository*, nothing called it
any more — 533 had already converted the only shipped legacy map. But its users
are **maps outside the repository**: every 2.4.2 Tidy map a player or author
already has.

**Measured consequence.** Loading the genuine 2.4.2 `maps/Tidy_Test.json`
through `EditorState.load_from_data` on the pre-fix tree:

    BEFORE: {'tidyobject': 42, 'playerstart': 1, 'light': 1,
             'tidyreceptacle': 1, 'tidygoal': 1}
    AFTER : {'playerstart': 1, 'light': 1, 'tidyreceptacle': 1, 'tidygoal': 1}
    ENTITIES LOST: 41

`Thing.from_dict` returns `None` for an unrecognised token and prints
`Warning: Unknown thing type 'tidyobject' found in map file.` to stdout;
`EditorState` drops it. A save afterwards makes the loss permanent. This is a
direct breach of the stated release requirement that **an unknown entity must
never simply disappear during load/save**.

538 also removed `map_uses_plugin`'s `tidyobject` branch, so a legacy map
containing only objects (no receptacle or goal) would not even auto-enable
Tidy — a second, independent break in the same commit.

**Fixed in this audit** by reverting 534–540 and adding
`tests/persistence/test_legacy_map_integrity.py`, which pins the real 2.4.2
record shape. After the fix: 0 entities lost, all 42 recognised by
`TidySession` with `tidy_category == "book"`, migration idempotent, and a
2.5-format map left untouched. Negative control confirms the tests fail when
the migration is disabled. See regressions.md REG-03 and fixes.md.

**The general hazard remains** and is worth a deliberate decision: `from_dict`
still silently drops *any* unknown type. A plugin that is missing or disabled at
load time takes its entities with it. Recorded in compatibility.md as
COMPAT-01 with two possible designs (preserve-and-round-trip unknown records,
or refuse the load).
